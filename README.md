# Reproducibility materials for "Free-support Wasserstein Resampling in Sequential Monte Carlo"

This archive reproduces every figure in the main text (Figures 1--7; the
manuscript contains no tables). Each figure is drawn by one command from the
results stored in `output/`, and the experiments that produce those results
are included as well. `make all` draws all seven figures at once.

## Contents

- `Makefile` — one target per figure.
- `code/plotting/` — the script that draws each figure.
- `code/experiments/` — one script per figure that runs its experiment
  (Figures 2--5).
- `code/simulation/` — the state-space models, the proposed and baseline resampling methods, simulation drivers, and evaluation metrics.
- `code/image_exp/` — the twisted diffusion sampler with the proposed and vanilla samplers.
- `data/` — data source; see `data/README.md`.
- `output/` — the stored intermediate results, as `.npz` tables, with the
  drawn figures written to `output/figures/`.

## Method implementations

The proposed methods are Wasserstein--Dirichlet resampling (WDR) and its
truncated variant (T-WDR). The following table groups the main implementation
files by their roles.

| Role | Main files and their purpose |
|---|---|
| State-space resampling | [ot_resampling.py](code/simulation/ot_resampling.py) implements WDR/T-WDR and classical baselines for state-space simulations. [hilbert_resampling.py](code/simulation/hilbert_resampling.py) provides Hilbert-curve stratified resampling. |
| Spatial block filtering | [hd_model.py](code/simulation/hd_model.py) defines the spatial model and block particle filter. [hd_wdr_batched.py](code/simulation/hd_wdr_batched.py) implements batched WDR for spatial blocks; [run_hd_filter.py](code/simulation/run_hd_filter.py) connects it to the filter. |
| Image resampling | [image_ot_resampling.py](code/image_exp/smc_utils/image_ot_resampling.py) implements WDR/T-WDR for VAE latent features in the image experiments. [smc_utils.py](code/image_exp/smc_utils/smc_utils.py) connects these methods to the SMC loop in [feynman_kac_pf.py](code/image_exp/smc_utils/feynman_kac_pf.py). |
| Models and experiment drivers | [lg_common.py](code/simulation/lg_common.py) defines the linear Gaussian model, data generation, propagation, and Kalman reference. The shell scripts in [code/experiments/](code/experiments/) launch the simulation drivers in [code/simulation/](code/simulation/). [run_image.py](code/image_exp/run_image.py) runs class-conditional image generation using [image_confs/](code/image_exp/image_confs/). |

To adapt the methods to a new setting:

- For a state-space model, follow the resampling calls in
  [run_lg_grid.py](code/simulation/run_lg_grid.py), replacing the model's
  initialization, propagation, and observation likelihood. Pass particles
  of shape `(N, d)`, normalized weights of shape `(N,)`, a NumPy generator,
  and the desired output size. 
- For a spatial model, use `hd_model.block_filter` as the example for
  defining blocks and local observation sets, and `run_hd_filter.py` for
  supplying the blockwise resampler.
- For diffusion image generation, start from `run_image.py` and
  `image_confs/` when adapting the diffusion model and conditioning tasks. 
  The `P`, `R` and `strategy` settings in the launch scripts control
  particle count, descendant expansion, and resampling method, respectively.

## Datasets

Figures 1--5 use simulated data generated by the supplied scripts.
Figures 6--7 use MNIST and CIFAR-10 for class-conditional image generation.
See [data/README.md](data/README.md) for dataset descriptions, sizes,
preprocessing, and their use in the experiments.

## Environment

```
conda env create -f environment.yml
conda activate wdr
```

Drawing the figures uses only python, numpy, matplotlib, and pillow, and runs
on any machine. The simulations also use scipy, POT, hilbertcurve, and
pytorch, and need a CUDA GPU; the image experiments need about 16 GB of GPU memory.

## Reproducing the simulation studies

Figures 1 to 5 of the paper.

### From intermediate results

Each command draws its figure from the results stored in `output/`, in
seconds and without a GPU:

| Command | Output file | Input |
|---|---|---|
| `make figure1` | `output/figures/fig1_toy.png` | no intermediate input files; the illustration is computed from scratch |
| `make figure2` | `output/figures/fig2_lg_grid.png` | `output/fig2_lg_grid/`: one row per run with its log RMSE and log energy score |
| `make figure3` | `output/figures/fig3_lg_stability.png` | `output/fig3_stability/`: one row per run and timestep, from which the estimate and RMSE standard deviations are recomputed, and the stored between-run energy distances |
| `make figure4` | `output/figures/fig4_lg_cost.png` | `output/fig4_cost/`: one row per run with its RMSE, energy score, and energy distance, and the recorded computing times that define the cost axis |
| `make figure5` | `output/figures/fig5_hd_cost.png` | `output/fig5_hd/`: one row per run with its RMSE, energy score, and energy distance, and the recorded computing times that define the cost axis |

### End to end

Each command below runs the complete experiment of its figure and writes its
results into `output/`. Then run the corresponding `make figureN` command above 
to recreate the figure from the new results. These experiments ran on an NVIDIA 
H100 GPU and take hours to days.

| Command | Runs |
|---|---|
| `bash code/experiments/fig2_lg_grid.sh` | the linear Gaussian grid over dimensions and condition numbers |
| `bash code/experiments/fig3_lg_stability.sh` | the repeated filter runs on one dataset |
| `bash code/experiments/fig4_lg_cost.sh` | the performance--cost study over sub-step multipliers, particle sizes, methods, and replications |
| `bash code/experiments/fig5_hd_filter.sh` | the block particle filter comparison on the spatial model |

## Reproducing the image experiments

Figures 6 and 7 of the paper.

### From intermediate results

| Command | Output file | Input |
|---|---|---|
| `make figure6` | `output/figures/fig6_image_metrics_vs_cost.png` | `output/fig6_image/`: the image metrics and their computing times |
| `make figure7` | `output/figures/fig7_tds_samples.png` | `output/fig7_samples/`: the eight generated image grids |

### End to end

These experiments ran on an NVIDIA H100 GPU and take days.

**Step 1: download the pretrained checkpoints.**

```
cd code/image_exp
python download_ckpts.py
```

Pulls four files (~645 MB) from
`Mengyu8042/wdr-checkpoints` into `code/image_exp/models/`:

- `uncond_model_mnist.pt`
- `uncond_model_cifar10.pt`
- `classifier_mnist.pth.tar`
- `classifier_cifar10.pth.tar`

**Step 2: generate the MNIST samples.**

```
bash run_mnist.sh
```

**Step 3: generate the CIFAR-10 samples.**

```
bash run_cifar10.sh
```

In each launch script, `strategy` selects the resampling method: `t-wdr` and `wdr` 
for the proposed methods, `systematic` for the vanilla one.

Each run writes its results to
`outputs_<dataset>/class_cond_gen/<sampler_full_name>_data...<timestamp>/`,
which contains:

- `config.yml`: full resolved sampler/task/model config.
- `metrics_details.csv`: one row per (label, replication) iter.
- `metrics_summary.json`: aggregated results.
- `samples/`: PNG grid for the first
  `save_output_i` iters.
- `all_samples.npz`: every generated sample
  with its label and replication index.
